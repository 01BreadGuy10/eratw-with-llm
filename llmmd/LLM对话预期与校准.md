# LLM 对话系统 —— 预期表现与"度"的校准

> 这份文档回答一个问题：**这一整套组合拳下来，角色到底会演成什么样？**
>
> 用法：拿它当"标尺"。实际玩的时候对不上，就在这份文档里找到对应的格子，
> 那份差异就是需要调的参数。
>
> ⚠️ 文档里的对话是**推演**（基于 prompt 内容推测），不是实测记录。
> 实测到的不一样是正常的 —— 差别本身就是信息。

---

## 〇、先明确：有哪些东西在同时说话

一轮对话里，同时注入 prompt 的**影响说话的模块**有这些：

| 模块 | 影响什么 | 强度 |
|---|---|---|
| persona / 口上剧本 | 基本人设与语气 | 强（基底）|
| `LLM_TONE` | 句尾风格（口調 + 性格傾向）| 中 |
| `LLM_CHARA_TRAIT`（手写）| 说话习惯 | 中 |
| **角色介绍**（官方）| 她是什么人 | 弱（背景）|
| **性格类型**（官方）| 定性 | 弱 |
| **人际关系**（官方）| 她跟谁好 | 弱（背景）|
| `LLM_CHARA_FEATURE` / `_LIKES` | 特性 / 爱好 | 中 |
| `LLM_MEMO` | 持久记忆（20 分钟冷却）| 中 |
| `LLM_PREV` | 上一场对话 | 弱 |
| `LLM_REL` / `LLM_ATT` / `LLM_CONSENT` | 关系 / 合意 / 既成事实 | **强** |
| `LLM_MOOD` / `LLM_ACT` / `LLM_PLACE` / 天气 | 当下状态 | 强 |
| `LLM_SCHED`（四档 × 四种性格）| 时间压力 | 中 |
| `LLM_HORNY`（新增）| 欲求不满 + 按关系的表现 | **强** |
| `LLM_LUST`（憋着）| 想要但地方不对 | **强** |
| `LLM_PTIRED` | 他快撑不住了 | **强** |
| `LLM_WANT_SLEEP` | 她要收尾去睡 | **强** |
| `LLM_BYE_MODE` | 送别 / 挽留 | **强** |
| 【当前的事实】 | 压过历史的硬定性 | 最强 |

**⚠️ 加粗的那些都是"强"** —— 也就是说，**最多可能有 6 个强信号同时出现**。
这正是下面第 8 节要谈的最大风险。

## 一、按关系阶段推演（主轴线）

### ① 档位 0 · 陌生 · 灵梦（懒散）· 白天 · 欲求 150

**prompt 里的关键内容**
```
【与玩家的关系】初次见面
【你现在的身体状态】——（积攒度 < 200，不注入）
【你今天的安排】今天是周三，你休息，不用上班
【你现在的身体状态】（无）
```
**注意：没有记忆、没有既成事实、人际关系是背景**

> 玩家：「你今天也在神社啊」
> 她：「嗯——不然呢，这儿是我的地盘。……有事？」

> 玩家：「那我先走了」
> → **挽留率 5%** ⇒ 基本放行
> 她：「哦，慢走。」

**度评估：✅ 正常。** 话短、不热情、不多说 —— 符合"陌生 + 灵梦"。

---

### ② 档位 1 · 认识 · 小伞（坦率、笨拙）· 凌晨 00:30（睡前 1 小时）

**prompt 里的关键内容**
```
【与玩家的关系】认识的人
【时间上的事】眼皮开始发沉，你有点困了        ← 若她是弱势系；坦率系则是"你有点困了"
【你和别人的关系】早苗（很不对付）、白莲（关系很好）
```
> 玩家：「还不睡啊」
> 她：「唔……再待一会儿嘛。你看，晚上的寺院也挺好的。」
> 玩家：「那我先去睡了，晚安」
> → 挽留率 10%，**但她自己在 1 小时内要睡 ⇒ 压到 0** ⇒ **接受**
> 她：「嗯，晚安。……我也该去睡了，再熬下去明天又要睡到中午。」

**度评估：✅ 很好。**
"顺口说自己也要走"那句就是**挂钩生效**的证据 —— 这是这一整套里最自然的一环。

---

### ③ 档位 2 · 思慕 · 任意角色 · 下午 · 欲求 350

**prompt 里的关键内容**
```
【与玩家的关系】对你有好感（思慕）
【你现在的身体状态】你现在的状态：心里有些燥，但还没到忍不住的地步（欲求 35％）。
   但你们还没到那一步，所以你只会自己难受，不会表现出来 ——
   · 说话偶尔走神、反应慢半拍，或者莫名有点烦躁
   · 绝不主动暗示、也绝不勾引
```
> 玩家：「今天天气不错啊」
> 她：「嗯……啊、对，是不错。」
> （走神了半秒才接上）

**度评估：✅ 好。** 「走神半拍」这个表现**很轻**，不会 OOC。

**⚠️ 这是"浅关系"分支的价值**：同样是欲求 35%，
如果换成"深关系"分支，她就会去撩他 —— **那就完全不合适了**。

---

### ④ 档位 3 · 恋慕 · 帕秋莉（无口、冷淡）· 下午 · 欲求 600

**prompt 里的关键内容**
```
【与玩家的关系】爱慕着你（恋慕）
【你现在的身体状态】你现在的状态：欲求不满，时不时会走神（欲求 60％）。
   你们关系够近，所以你会用这些方式让他察觉 ——
   · 视线在他身上多停一会儿、被看到又移开
   · 找理由靠近、碰一下他的袖子/肩膀
   · 话说到一半留个尾巴，等他接
```
> 玩家：「今天在看什么书？」
> 她：「……嗯？啊、这本，讲魔法的。」
> （视线在他身上多停了一秒，然后移开）

**⚠️ 度评估：这里开始有风险。**
帕秋莉是**无口 / 冷淡**型，`@LLM_CHARA_TRAIT` 给她的定位是"话少、不爱解释"。
而 `LLM_HORNY` 的深关系分支是**通用的**（对所有深关系角色都说"会用眼神、找理由靠近"）——
**它不知道"这个角色本来就不会主动"**。

**⇒ 可能的结果**：帕秋莉做出"碰他袖子""留半句话等他接"这种动作，
**技术上不算 OOC（恋慕确实会心动），但和她一贯的表现落差太大**。

**📌 这是第 8 节风险 #2 的具体形态。**

---

### ⑤ 档位 4 · 恋人 · 咲夜（认真系）· 傍晚 · 她快上班

**prompt 里的关键内容**
```
【与玩家的关系】恋人
【时间上的事】快到上班时间了，你在心里盘算着别迟到    ← 认真系措辞
【你今天的安排】今天是周三，你的工作是女仆（在红魔馆）…
```
> 玩家：「我该走了」
> → 挽留率 **80%**，**但她 1 小时内要上班 ⇒ 压到 0** ⇒ **接受**
> 她：「嗯，路上小心。——我得去准备晚饭了，今晚有客人。」

**度评估：✅ 好。**
**⚠️ 注意这里的设计张力**：关系最亲密（最想留人），
但**她自己的日程把她自己也推走了** —— 于是台词变成"舍不得但没办法"，
比单纯的挽留更有味道 ✓

### ⑥ 档位 5 · 炮友 · 任意角色 · 深夜 · 欲求 900

**prompt 里的关键内容**
```
【与玩家的关系】炮友关系
【你现在的身体状态】你现在的状态：焦躁难忍，一点小事就能撩动你（欲求 90％）。
   你们关系够近，所以你会用这些方式让他察觉 ——      ← ⚠️ 见下面的问题
```
**⚠️⚠️ 这里有个语义问题**：`@LLM_REL_DEPTH` 把**炮友归为"中"（1）**，
所以 `LLM_HORNY` 走的是**"只自己难受、绝不勾引"**那一条分支。

**⇒ 结果是：一个"炮友关系"的角色，欲求 90%，却被告知"绝不主动暗示"。**

**⚠️ 这可能不符合玩家直觉** —— 炮友关系里，"想要就说/就做"才是常态。

**📌 这是需要你决定的一个点**（见第 8 节风险 #5）。

---

### ⑦ 档位 6 · 爱欲 · 任意角色 · 深夜 · 欲求 1000

```
【与玩家的关系】沉溺于欲望（爱欲）
【你现在的身体状态】整个人饥渴难耐，几乎没法想别的事（欲求 100％）。
   你们关系够近，所以你会用这些方式让他察觉…
```
**度评估：⚠️ 这是全套里最强的一档。**
"饥渴难耐" + 深关系表现 + **收尾去睡率 0（永远不赶你走）** +
**你累了也不赶**（只有 `@LLM_TOO_TIRED` 硬刹车）…

**⇒ 她会一直陪着、一直撩** —— 这正是你要的"陪着熬夜到昏厥" ✓
**⚠️ 但要小心它变成"每轮都在撩"**（见风险 #1）。

## 二、按"性格 × 作息"推演（新加的措辞分化）

| 性格 | 睡前 1 小时 | 该睡没睡 | 刚睡醒 |
|---|---|---|---|
| 弱势系 | 眼皮开始发沉，你有点困了 | 你困得快撑不住了，只是还没走 | 脑子还有点迷迷糊糊 |
| **强势系** | **你嘴上不承认，其实已经有点困了** | **你硬撑着装作没事，其实困得厉害** | **还没醒透，但不想让人看出来** |
| 坦率系 | 你有点困了 | 你很困，只是还没走 | 还有点没睡醒 |
| 认真系 | 你注意到自己有点困了，注意力已经开始散 | 你在强打精神，心里清楚这样效率很差 | 状态还没完全回来 |

**预期效果**：同样是"困了"，
- 强势系会演成「……我才不困。你哪只眼睛看见我困了。」
- 弱势系会演成「唔……有点撑不住了……」
- 认真系会演成「……我还有两页没看完，看完就睡。」

**度评估：✅ 分化有效，而且成本极低**（16 条字符串）。

## 三、玩家道别的完整分支表

| 关系 | 挽留率 | 她自己的日程 | 实际结果 |
|---|---|---|---|
| 陌生 | 5% | — | 基本放行，话很短 |
| 认识 | 10% | — | 基本放行 |
| 思慕 | 30% | — | 三次里有一次会留 |
| 恋慕 | 55% | — | 更容易留 |
| **恋人** | **80%** | — | **基本都会留** |
| 恋人 | 80% | **1 小时内有班/要睡** | **压到 0 → 放行，但会说自己也该走了** |
| 任意 | 任意 | **玩家快撑不住** | **压到 0 → 心疼地放行** |
| 任意 | 任意 | **本场已挽留过一次** | **压到 0 → 放行** |

**度评估：✅ 这张表的设计我认为是稳的** ——
三个"压到 0"的修正都在**该放你走的时候放你走**，
不会出现"她明明要上班还死缠着你不放"这种明显不合理的情况。

## 四、⚠️ 风险清单（"度"可能过头的地方）

> 这一节是这份文档最重要的部分。

### 风险 #1 · 欲求不满注入**没有冷却** ⚠️⚠️

**现状**：`LLM_HORNY` 只要 `积攒度 >= 200` 就**每轮都注入**。

**⇒ 一场 20 轮的对话里，她被提醒 20 次"你欲求不满"。**
模型的反应必然是**每轮都往那方面带**。

**对比**：持久记忆我们**专门加了 20 分钟冷却**（§31），就是因为"每轮都摊在她面前
她会一直提"。**欲求不满是同一个机制问题，但还没加冷却。**

**⇒ 建议**：照抄记忆那套冷却（`TCVAR` 存上次注入时间，隔 N 分钟才再注入一次）。
**或者更轻**：注入时加一句"**绝大多数轮次不用表现**"。

**📌 我的判断：这是当前最可能需要调的一项。**

---

### 风险 #2 · `LLM_HORNY` 的"表现方式"**不看角色性格** ⚠️⚠️

**现状**：深关系分支对所有角色都说"会用眼神、找理由靠近、留半句话"。

**⇒ 帕秋莉（无口）、咲夜（认真）、灵梦（懒散）会用同一套动作。**

**对比**：`LLM_SCHED` 我们**专门按性格分了四套**，`LLM_CHARA_TRAIT` 也是逐角色手写的 ——
**只有 `LLM_HORNY` 漏了这一层。**

**⇒ 建议**：给深关系分支也加性格修正
（强势 → 直接上手/挑衅；弱势 → 眼神+脸红；坦率 → 直接说；认真 → 找借口靠近）。

**📌 我的判断：这是"角色辨识度"损失最大的地方。**

---

### 风险 #3 · 恋人挽留 **+3333** 可能太快 ⚠️

**现状**：挽留一次 = 上限的 1/3。恋人上限 9999 ⇒ **+3333**。

**⇒ 被挽留 3 次就满了**，然后长期停在"❤饥渴难耐❤"，配合"收尾率 0"
⇒ 她**长期处于最饥渴状态且永远不赶你走**。

**⚠️ 这可能是"过猛"的**：玩家会很快失去"从平静到饥渴"的过程感。

**⇒ 几个可选旋钮**（我没动，等你定）：
- 改成 **1/4 上限**（恋人 +2500，4 次满）
- 加**每场对话只加一次**的限制
- 加**递减**（同一场第二次挽留只加一半）
- 给恋人也设一个**软上限**（如 5000），别让它天天顶着 9999

**📌 我的判断：数值本身不算离谱，但"3 次到顶"偏快。**

---

### 风险 #4 · 强化信号**同时出现在一轮** ⚠️⚠️⚠️

**这是最需要盯的一项。**

一轮 prompt 里**最多可能同时出现**：

```
【他的状态】他快撑不住了（LLM_PTIRED）
【时间上的事】你困得快撑不住了（LLM_SCHED ③）
【你现在的身体状态】你饥渴难耐…（LLM_HORNY）
【你现在的身体状态】你很想要他，但这里不合适（LLM_LUST）
★★ 他刚才是在跟你道别，但你不想让他走（LLM_BYE_MODE）
★★ 你困得实在撑不住了，这一轮就打算收尾去睡（LLM_WANT_SLEEP）
```

**⇒ 她可能在同一句话里同时演"心疼他累 + 自己困 + 想要他 + 舍不得他走 + 要收尾"**
—— 结果是一锅粥，或者模型只能挑一个演（挑哪个不确定）。

**现状**：我**只处理了一处互斥**（`LLM_HORNY` 和 `LLM_LUST` 互斥）。

**⇒ 建议加一层"本轮主打"规则**：
- 优先级：**推倒 > 玩家道别 > 她要收尾去睡 > 他很累 > 欲求不满 > 作息提醒**
- 只让**最高的两个**注入，其余的降级成一句轻描淡写

**📌 我的判断：这是最影响"像不像活人"的一项。**
真人也不会在同一句话里汇报五个状态。

---

### 风险 #5 · 炮友关系被归为"中深度" ⚠️

**现状**：`@LLM_REL_DEPTH` 把炮友（档位 5）和思慕一样归为"中"（1）。

**⇒ 炮友欲求 90% 时，她被告知"绝不主动暗示、绝不勾引"。**

**⚠️ 但这可能不符合直觉** —— 炮友关系的定义就是"有肉体关系"。

**⚠️ 不过**：`@LLM_REL_DEPTH` 的"中"是**忠实照抄了原代码**的
（`@LLM_TRY_PUSH` 的 `恋慕||爱欲` 不含炮友、越界反应也不含炮友）。

**⇒ 所以要么两处一起改，要么两处一起保持。**
**📌 这个得你定**：炮友关系里，她应该"想要就表现出来"吗？

---

### 风险 #6 · prompt 长度 ⚠️

**现状**：`sysLen` 之前实测平均 **6916 字**，
新增（角色介绍 + 人际关系 + 性格 + 欲求不满）约 **+300~450 字**。

**⇒ 预计 7200~7400 字**（折合 token 约 4300~7400）。

**⇒ 还好**，但值得实测确认一次（看 `plugins\LLMBridge\debug.log` 的 `sysLen`）。

---

### 风险 #7 · 收尾去睡 与 玩家道别 撞车

**现状**：两者都会 `BREAK`，优先级已定（道别在前）。

**⇒ 如果玩家说"我走了"而她同时想睡**：先按"道别"处理（她送别）
⇒ **她自己的困意就不会被说出来** ⚠️ 小问题，可接受。

## 四之二、★ 按你的定调已改的三项（#1 #2 #5）

### #2 `LLM_HORNY` 的表现方式 → **加性格分化** ✅

原来深关系分支对所有角色都是同一套动作，现在按 `性格傾向` 分四套：

| 性格 | 她怎么表现 |
|---|---|
| **1 弱势系** | 视线躲闪、耳根发烫、声音变小；**想靠近又不敢**；**不会主动开口**，只把「我有点不对劲」露在脸上 |
| **2 强势系** | 直白、带挑衅（「你今天倒是老实」）；**主动凑近、抓袖子**；**但别直说「我想要」** |
| **4 认真系** | 用**正当理由**制造接触（「你领子歪了」）；一本正经说着话手却不听话；**被点破会转移话题** |
| 坦率系 / 无 | 老实承认走神；主动靠近找由头多待一会儿；**别太露骨** |

**⇒ 这样帕秋莉（无口）、咲夜（认真）、灵梦（懒散）就不会做同一个动作了。**

### #5 炮友 → 归入"深"（可以主动勾引）✅

`@LLM_REL_DEPTH` 里把**炮友（档位 5）**从"中"移到了"深"。

**⚠️ 说明**：这**不是**照编号大小排的（思慕 2 < 恋慕 3 < **炮友 5**），
纯粹按语义 —— 炮友的定义就是"有肉体关系"，所以她**可以主动**。
（这个函数存在的理由正在于此。）

**⚠️ 但有一处我没动，你可以再定**：
`@LLM_TRY_PUSH`（她主动推倒你）的准入条件仍然是 `恋慕 || 爱欲`，**不含炮友**。
- **勾引 ≠ 推倒** —— 所以"只改 DEPTH"严格满足你说的"可以主动勾引" ✓
- 但如果你觉得**炮友也该能推倒你**，告诉我，一行就改完。

### #1 按数值分强度（不是一刀切）✅

### 二、最坏情况会是什么样（真实推演）

**场景**：恋慕 + 欲求 1000 + 深夜（她早该睡了）+ 玩家很累 + 玩家说「我走了」

★★ 你困得实在撑不住了，这一轮就打算收尾去睡
```

**⚠️ 这里的问题是反高潮**：

- 前四条其实指向**同一个收尾场景**（他累 → 该散了 → 你也要睡）✓ 很连贯

>   不过说真的，我现在有点想要你。……那我先去睡了，你路上小心。」

**⇒ 这不是"活人"，这是"状态面板念了一遍"。**

### 三、★ 事实层 / 行动层的拆分（本次设计的核心）

ENDIF
```

**⇒ 事实可以有很多条，行动只能有一个。真人也正是这样** ——
她知道很多事，但每句话只做一件事。

### 四、总规则：**"上面那些是状态，不是清单"**

**即使指令只剩一条，事实层仍然有好几条同时在场**，模型还是倾向逐条回应。
所以最后加了一段**收口规则**：

```
【最重要的表达规则】
⚠️⚠️ 上面列了很多项信息（时间 / 天气 / 你的状态 / 他的状态 / 关系 / 记忆…）——
   它们是你此刻知道的事，不是你要说的话。

   · 全都说出来就变成汇报了，不像人在说话。
   · 绝大多数信息，这一整场对话里一次都不提，才是正常的。

```

**⚠️ "绝大多数信息一次都不提才是正常的"** 这句是刻意的 ——
**必须给它"可以不说"的许可**，否则它会觉得有义务汇报。

| **困意** | ✅ 影响 ACTION 5 | 事实保留（快上班 / 有困意 / 刚醒 这三档**不产生行动码**）<br>结论体现在 ACTION 5 |
| **体力/气力** | ✅ 影响 ACTION 4 | 结论体现在 ACTION 4；<br>**约束**（"别答应陪他"）仍无条件保留 |
| **性格** | ❌ 不参与判定 | 作息措辞（四套）+ **欲求表现方式（四套）** |
| **人际关系 / 角色介绍** | ❌ | 背景层，全程注入 |

**⇒ 结论：所有对话都和好感度、欲求联动** ✅（补完 CASE 0 之后）

### 四、闲聊档实际注入的样子

```
【这一轮你打算怎么做】（这一轮你们就是在闲聊，没有什么特别的事要办。）
   但你的状态会顺着话自然流露出来，不用刻意藏：
   · 关系：你舍不得他 —— 这不是客套，是你真的不想让他走。
   · 身体：你现在的状态：欲求不满，时不时会走神（欲求 60％）。
     你们关系够近，所以你会表现出来，方式是坦率系的 ——
     · 会老实承认自己有点心不在焉（「……刚才走神了」）
     强度：会控制不住地多看他几眼，然后自己先移开。
   ⚠️ 但**这些都只是流露** —— 正常聊你要聊的事，
      **别专门提起它、也别把话题往那儿引**（那是另一回事）。
```

**⇒ 这样"闲聊"才不是"没有联动"，而是"**联动得更轻**"。**

## 六、一句话总结

**这套系统现在的问题不是"不够强"，而是"可能同时太强"。**

每个模块单独看都很合理，但**它们都往同一个方向使劲**
（"她喜欢你" → 记忆多提、欲求多表现、舍不得你走、不赶你睡）。

**⇒ 真正要调的往往不是"加什么"，而是"什么时候不加"。**
