# 怎么把「版本更新说明」发到 GitHub

> 写给**没做过这件事**的人。照着做就行。
> 你的仓库：<https://github.com/01BreadGuy10/eratw-with-llm>

---

## 一、先搞清楚三个东西是什么

| 名字 | 是什么 | 在哪看 |
|---|---|---|
| **Commit（提交）** | 「我改了代码」这个动作本身 | 仓库的 **Commits** 页 |
| **Tag（标签）** | 给某一次提交起个版本名，比如 `v1.0.0` | 仓库的 **Tags** 页 |
| **Release（发行版）** | **给玩家看的"更新说明"页面** —— 有标题、有说明文字、能挂下载包 | 仓库的 **Releases** 页 |

**⇒ 你问的「版本更新说明」= Release** ✓

**⇒ 发 Release 需要先有一个 Tag**（网页上创建 Release 时可以顺便新建 Tag，不用命令行）。

**⇒ `CHANGELOG.md`** 是仓库里的**文件**，记录**所有**版本的更新（技术向、完整）。
**⇒ Release** 是**网页上的公告**，通常只写**这一版**给玩家看的重点。

**⇒ 两个不冲突，建议都做**：
- `CHANGELOG.md` → 完整记录（方便以后查）
- Release → 这次更新的公告（方便玩家看）

---

## 二、推荐做法：在网页上发 Release

### 第 0 步：先把 CHANGELOG.md 提交上去

`CHANGELOG.md` 我已经写好放在仓库根目录了。你需要把它提交并推送：

```powershell
cd "E:\Program Files (x86)\eratw-sub-modding-main\eratw-with-llm"
git add CHANGELOG.md "llmmd/发布指南_怎么发版本更新.md"
git commit -m "添加更新日志与发布指南"
git push
```

> ⚠️ 如果 `git push` 要求登录：按提示走浏览器授权即可（第一次会弹窗）。

---

### 第 1 步：打开 Releases 页面

浏览器打开：

```
https://github.com/01BreadGuy10/eratw-with-llm/releases
```

**⇒ 因为还没发过版本，页面会显示「There aren't any releases here」+ 一个按钮。**

点右边的 **`Draft a new release`**（起草新发行版）。

---

### 第 2 步：创建 Tag

页面顶部有个 **`Choose a tag`** 的下拉框：

1. 点开它
2. 在输入框里打 **`v1.0.0`**
3. 下面会出现一行 **`Create new tag: v1.0.0 on publish`** ⇒ **点它**

**⇒ 意思**：等会点发布时，GitHub 会自动在最新的提交上打这个标签 ✓

> 💡 **版本号怎么起？**
> - **首次发布 ⇒ `v1.0.0`** ← 你现在就是这一版
> - 修 bug、小改动 ⇒ `v1.0.1`
> - 加功能 ⇒ `v1.2.0`
> - 大改 / 不兼容 ⇒ `v2.0.0`
> - **随便起也行**（比如 `v2026.10.09`），只要以后别重复 ✓

---

### 第 3 步：填标题和说明

| 字段 | 填什么 |
|---|---|
| **Release title** | `v1.0.0 —— 自由互动：脱衣 / 立绘 / 身体状态修复` |
| **描述框**（大文本框） | 粘下面的内容 ↓ |

**⇒ 可以直接从 `CHANGELOG.md` 里复制 `## [v1.0.0]` 那一段**，
**⇒ 或者粘这份更简短的「玩家版」**：

```markdown
## 这一版修好了什么

### ★ 脱衣后立绘不更新 —— 修好了
以前在自由互动里脱掉衣服，立绘还是穿衣服的，得重开互动才刷新。
现在改用游戏自己的显示接口（和外面 Look 界面同一条路径），**每轮都会跟着衣服变**。

### ★ 脱内裤总说「外面还穿着」—— 修好了
蝴蝶结这类装饰件被误当成了「外衣」，把自己挡住了。
现在**装饰件不算上下衣**，说得出名字就能脱。

### 穿着显示更清楚了
【穿着】那行现在会列出**装饰件**（饰品 / 腕部 / 蝴蝶结…）
⇒ 一眼能看到身上还有什么能脱。

### 欲求不满 = 性欲，不是心情不好
以前模型会把它演成「烦躁、走神」，现在 prompt 里写明了：
这是**想做爱的程度**，越高越想要眼前这个人。

### 赤裸时的语境锁定了
上半身或下半身赤裸时，会明确告诉她「前戏进行到后期 / 已结束」
⇒ 不会再出现「人都脱光了却在聊别的事」。

### 思考链不再泄漏
收紧了检测并扩充了特征词，大段的内心分析不会再被当台词念出来。
```

---

### 第 4 步：发布

1. （可选）勾选 **`Set as the latest release`** —— 表示这是最新版 ✓
2. （可选）如果**没有**打包文件要上传，**附件区留空就行**（源码会自动以 zip/tar.gz 提供）
3. 点绿色的 **`Publish release`**

**⇒ 完成！** 页面会跳到 Release 详情页，玩家就能看到了 ✓

## 三、另一种做法：命令行打 Tag（网页只用来写说明）

如果你更喜欢命令行：

```powershell
cd "E:\Program Files (x86)\eratw-sub-modding-main\eratw-with-llm"

# 打一个带说明的标签（annotated tag）
git tag -a v1.0.0 -m "v1.0.0 自由互动：脱衣/立绘/身体状态修复"

# 推送标签
git push origin v1.0.0
```

然后：

```
https://github.com/01BreadGuy10/eratw-with-llm/releases/new
```

⇒ 在 `Choose a tag` 里就能**选到** `v1.0.0`（不用新建）⇒ 后面的步骤一样 ✓

## 四、最省事的做法：只提交 CHANGELOG.md

如果你**不想发 Release**、只想让大家能看到更新记录：

```powershell
git add CHANGELOG.md
git commit -m "更新日志 v1.0.0"
git push
```

⇒ 之后任何人打开仓库，都能在文件列表里看到 `CHANGELOG.md` ✓
⇒ 但**没有 Releases 页面的"公告"效果**。

## 五、常见疑问

**Q：以后每次更新都要发 Release 吗？**
不用。**攒够一批值得说的改动**再发一个版本就行。中间的小修可以直接 commit。

**Q：Release 和 CHANGELOG 内容要一样吗？**
不需要。Release 写给玩家看（**只说功能变化**），CHANGELOG 写给自己/开发者看（**含内部修复**）。

**Q：发错了能改吗？**
能。Release 页面右上角有 **铅笔图标（Edit release）**，改完保存即可；
Tag 也能删（Releases 页面点 tag 名 → `Delete`）。

**Q：会不会把我本地的东西传上去？**
不会。`.gitignore` 已经挡住**存档（`sav/`）**、**编辑备份文件**、**`__pycache__`**、
**临时脚本（`_*.py`）**、**`apis.txt`（API 密钥）**。

**Q：怎么确认存档真的没上去？**
```powershell
git ls-files | Select-String 'sav/|\.sav$'
```
**⇒ 输出为空 = 安全** ✓

## 六、一句话流程（备忘）

```
改代码 → git add / commit / push  →  打开 Releases 页
      →  Draft a new release  →  新建 tag（如 v1.2.0）
      →  填标题 + 粘贴说明  →  Publish release  ✓
```
