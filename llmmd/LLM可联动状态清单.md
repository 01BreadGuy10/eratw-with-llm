## ★ 追加调研：「親密」与「欲望」这两个 ABL 怎么涨（官方机制）

> 用户问："官方的欲望值和亲密值的获得方式是什么？"
> 结论：**两个都只在"亲密行为"里涨，自由对话碰不到** ——
> 所以如果想让对话影响它们，**那是新增功能，不是"照抄官方"**。

### 一、它们是什么

`CSV\ABL.csv` 里的**基本能力**（不是技能）：

```
9,親密      10,従順      11,欲望      12,技巧      13,奉仕精神
```

**⚠️ 编号 < 40 ⇒ 显示用 `MAX_99` 尺度（10 档 ＳＳＳ~Ｇ），不是技能的 7 档** ✓
（`PRINT_STATE.ERB:307-311`：`IF LOCAL < 40 → "MAX_99" ELSE → "MAX_6"`）

**实际范围 0~20** —— 例如 `M_KOJO_K11_2_イベント.ERB:4396` 里就是
`ABL:11:親密 == 20 && ABL:11:欲望 == 20`。

**⇒ 折 10 档**：`20 = Ａ`、`10 = Ｂ`、`5 = Ｃ`、`3 = Ｄ`、`0 = Ｇ`

### 二、「欲望」(ABL 11) —— **由她达到的高潮强度决定**

**唯一来源**：`TRACHECK_ORGASM.ERB:563-589`「絶頂による欲望ＬＶUP」

| 条件 | 欲望 |
|---|---|
| 普通绝顶（Ｃ/Ｂ/Ｖ/Ａ 任一）| 1 |
| Ｖ 或 Ａ 强绝顶 / Ｍ 绝顶 | 3 |
| 二重绝顶 | 6 |
| 三重 / 四重 / 五重绝顶 | 9 / 12 / 15 |
| **有 `TALENT:自制心`** | **−1** |

**⚠️ 三条重要规则**：
1. **只升不降** —— `IF ABL:欲望 < LOCAL` 才赋值（取历史最高）
2. **`SOURCE:魔力印记 == 1` 时会抑制**（不涨，还打一句台词）
3. **另有一条特殊途径**：`AFTERTRA.ERB:188`「处女的觉醒」直接设 **20**

**⇒ 所以"欲望"= **她体验过的最强烈的那一次**，是个"经历"型数值，不是状态。**

### 三、「親密」(ABL 9) —— **由 `PALAM:好意` 的档位决定**

**主来源**：`TRACHECK_好感度上昇処理.ERB:430-444` `@YUKIZURI_BONUS`

```erb
TFLAG:97 *= 10                        ; 好感度 ×10（"雪钓"加成）
SIF CFLAG:ARG:体目当て
	TFLAG:97 *= 2                     ; 再看"体目当て"翻倍
LOCAL = GETPALAMLV(PALAM:ARG:好意,10) - 1
CALL YUKIZURI_BONUS_1(ARG, "親密", LOCAL)     ; ← 親密
LOCAL = GETPALAMLV(PALAM:ARG:習得,3)          ; → 技巧
LOCAL = MAX(GETPALAMLV(PALAM:恭順,3), GETPALAMLV(PALAM:屈服,3))  ; → 従順
LOCAL = GETPALAMLV(PALAM:ARG:恭順,3) - 1      ; → 奉仕精神
```

而 `@YUKIZURI_BONUS_1` 同样是**只升不降**：
```erb
SIF ABL:C_ID:CHK_ABL >= ARG
	RETURN                 ; 已经更高就不动
ABL:C_ID:CHK_ABL = ARG
```

**其它来源**：
| 来源 | 效果 |
|---|---|
| **满好感 + 信赖度补正** `EVENTTURNEND.ERB:23-28` | `CFLAG:2 >= 1000000` 时 `親密 = SQRT(信赖度)/8` |
| 事件 `情事発覚.ERB` | `+= 2`（被人发现情事）|
| 口上事件（如 `M_KOJO_K16_1:236`）| `+= 1` |

### 四、⚠️ 一个容易误读的坑

`ABLUP.ERB` 里有一整套 `@ABLUP0`~`@ABLUP35`（自动成长入口），
**但里面没有 `@ABLUP9`（親密）** —— 列表是 0,1,2,3,4,10,11,12…

**而且 `@ABL_UP`（通用提升）整个被 `[SKIPSTART]` 包着** ⇒ **那套已经不生效了**。

**⇒ 别以为"有个通用函数在管它们"** —— 親密/欲望都是**事件驱动**的。

### 五、对它本身的"上限"判定

`ABL.ERB:148 @MAXABL`：
```erb
IF ABL:ARG >= 99
	RETURN 1                    ; MAX
ELSEIF ABL:ARG >= 5 && !TALENT:恋慕
	RETURN 1                    ; ★ 没恋慕时上限只有 5
ENDIF
```
**⇒ 但这是给 `@ABL_UP` 用的，而 `@ABL_UP` 已 SKIPSTART** ⇒
实际上限由各事件自己决定（最高见到 **20**）。

### 六、📌 对我们的意义

| 结论 | 说明 |
|---|---|
| **我们对它们是"只读不写"** | 代码里 3 处引用：2 处是注释，1 处是 `SOURCE:歓楽 += 70 + ABL:親密 * 50`（**读取**）|
| **两个值本身碰不到** | 只在亲密行为/事件里涨 ⇒ **自由对话天然无法影响** |
| **想让对话影响 = 新增功能** | 不是"照抄官方"，得自己定数值 |
| **显示要用 `MAX_99`** | 10 档 ＳＳＳ~Ｇ，**不是技能的 7 档** |
| **它们**只升不降** | 是"经历"，不是"状态" ⇒ **不适合当"她现在多想要"的指标** |

### 七、★ 顺带一个**必须知道的联动**（我们已经在用）

`親密` **不是只读的摆设** —— 它会**放大好感度收益**：

| 位置 | 作用 |
|---|---|
| `FAVOR_CALC` 开头 | `TFLAG:97 += (ABL:従順 + ABL:親密) / 2` ⇒ **每轮结算的白送好感** |
| 我们的 `@LLM_WORK_DO` | `SOURCE:歓楽 += 70 + ABL:親密 * 50` ⇒ **親密直接放大帮忙的好感源** |

**⇒ 所以「親密」越高，同样一次帮忙给的好感越多** —— 这是官方的成长曲线，
我们的数值设计**照抄了它**（不是自己拍的比例）✓

**⚠️ 最后一条尤其重要**：
如果你想要"她现在多想要"这个信息，**`ABL:欲望` 不是合适的来源**（它只增不减）。
**更合适的是我们已经在用的 `CFLAG:角色:积攒度`（欲求不满度）** ——
那个是**会涨也会消**的状态量 ✓

## ★ 追加调研：「带出去」的条件 + 「情绪」到底是不是心情

### 一、「带出去」= `COMF351 連れ出す`（日常系指令 · 等级 2）

**核心条件函数** `COMF351 連れ出す.ERB:296 @COM_351_CONDITION(角色)`：

| 返回 | 含义 | 条件 |
|---|---|---|
| **3** | **绿字（最佳）** | **`CFLAG:態度 > 0`** 或 `@CAN_IRAI_CHARA_GO_TOGATHER(角色)`<br>**且** `CFLAG:睡眠 == 0` **且** `CFLAG:行動 != 5`（不在工作）|
| 2 | 可执行（普通）| 已经在**同行**中（允许手动解除）／`CFLAG:败犬` ／其余兜底 |

（`CFLAG:態度` 是性方面的合意判定，见 `ATTITUDE.ERB`。）

**另外还有一层开关**（`COMF351 連れ出す.ERB:260`）：
```erb
IF !(Setting_FLAG:外出时可以带出去 && GMF_GETBIT("幻想乡大地图"))
	; 非大地图模式：要求没在约会中、且在家（或隙间客）
	SIF CHK_DATENOW(CFLAG:MASTER:约会中) → 0
	SIF IN_HOME(CFLAG:現在位置) == 0 && !IS_GAP_GUEST(TARGET) → 0
ELSE
	SIF IS_DATING_WITH_PLAYER(TARGET) → 0     ; 大地图模式：已经在约会中就不行
ENDIF
```

**⇒ 「带出去」需要开启**两个东西**：
① **设置项**「外出时可以带出去」（`实用设置.ERB:74`，默认 **0/禁止**）
② **`GMF_GETBIT("幻想乡大地图")`**（幻想乡大地图模式）

**⚠️ 设置界面自己写着「需要开启幻想乡大地图」** —— 没开的话这条指令等于没有。

### 二、⚠️ 「情绪」**就是**心情的计量值（用户的怀疑不成立）

**证据链：**

| # | 证据 |
|---|---|
| ① | `CSV\Base.csv` 里 `10,ムード` —— **编号 10 的真名是「ムード」(mood)** |
| ② | Chara CSV 里写的是 `基礎,情緒,1500`，位置正好在 `理性`(11) / `怒り`(12) **之前** ⇒ 顺序与 `ムード` 完全对应 |
| ③ | `INFO.ERB:2341 @INFO_EMOTION` **就是显示它的函数**： |

```erb
@INFO_EMOTION
LOCAL = LIMIT(BASE:TARGET:情緒 / 200, 0, 5)
PRINTFORM 情绪:
CALL HEARTMARK(LOCAL)                  ; ← 用❤的个数表示（0~5 颗）
SIF BASE:TARGET:情緒 == MAXBASE:TARGET:情緒
	SETCOLOR 255,51,153                ; 满值变粉色
IF ... && CHK_DATENOW(CFLAG:TARGET:约会中)
	PRINTFORM OverDrive!!              ; 满值 + 约会中 = OverDrive!!
```

**⇒ 游戏界面明确写着「情绪:❤❤❤」，用爱心数量表示** ⇒ **它就是心情的计量值** ✓
**⇒ 我们给它加减（`@LLM_APPLY_DELTA` 的 `LLM_D2`）是对的。**

### 三、★ 但确实存在**另一个**东西：`TALENT:心情`（编号 15）

`CSV\Talent.csv: 15,心情,;気分の良し悪しってあるよね`

**取值 `-1 / 0 / 1`**（差 / 普通 / 好），是个**天赋位**，不是计量值：

| 用处 | 位置 |
|---|---|
| **影响自然变动** | `BASE自然変動.ERB:31: IF TALENT:ARG:心情 < 0` |
| 影响外出事件 | `GO_OUT_EV00_良い雰囲気.ERB:16: TALENT:PAIR:心情 < 0` |
| 台词表现 | `FREE_ACT_16: 心情 == 1 ? 保持微笑 : 面无表情` |
| 由事件设置 | `DAILY_EV28 通い狼.ERB:397/476`、`MEDICAL_BILLS.ERB:107` |

**⇒ 所以两者是不同的东西，但**都叫得上"心情"**：**

| | `BASE:角色:情緒` | `TALENT:角色:心情` |
|---|---|---|
| 类型 | **BASE**（0 ~ MAXBASE）| **TALENT**（-1 / 0 / 1）|
| 界面 | ✅ 显示（`情绪:❤❤❤`）| ❌ 不直接显示 |
| 语义 | **心情的计量值** | **心情的定性标记** |
| 我们用了 | ✅ `LLM_MOOD` / `LLM_D2` | ❌ 没用 |
| 特点 | **会涨会消**（`BASE自然変動` 每回合衰减）| **持续**，影响自然变动的方向 |

**📌 可考虑的新联动**：`TALENT:心情` 是**持续状态**，
如果对话能改变它（比如"聊得很开心" → `心情 = 1`），
效果会**延续到之后的回合**（因为它影响 `BASE自然変動`）——
比只加一次情绪值更"有后劲"。**要不要做由你定。**

## ★ 追加调研：「身体触碰」她什么时候不反感

**指令**：`COMF302 スキンシップ`（日常系 · 等级 1）

### 一、能不能执行 —— **⚠️ 没有好感度门槛**

`COMF302 スキンシップ.ERB:178 @COM_ABLE302`：

| 条件 | 要求 |
|---|---|
| `TFLAG:100` | 必须为真 |
| **1 小时间隔** | `TIME_PROGRESS(TCVAR:303) >= 60` **或** 正在约会 |
| 睡着 / 陪睡中 | ✗ |
| 工作中（`CFLAG:行動 == 5`）| ✗ |
| 玩家气力 ≤ 0 | ✗ |
| `FLAG:70`（停止中）| ✗ |

**⇒ 陌生人也能摸** —— 判定不在"能不能执行"，而在"**效果好不好**"。

### 二、成败判定（`:21-43`）

| 结果 | 概率 | 标记 | 信赖 |
|---|---|---|---|
| **大成功** | 10%（受玩家技巧/魔法加成）| `TFLAG:193 = 1` | **+1** |
| 成功 | 其余 | `= 0` | — |
| **失败** | 10~1%（`>= 90 + 成功率/5`）| `= -1` | **−2** |

### 三、★ 「不反感」的真正判据 —— **`ABL:親密` 和 `CFLAG:2` 两个都要够**

`:121-144`：
```erb
LOCAL = 0
; 親密が低いと好感度低下
IF ABL:親密 == 0    → LOCAL -= 3
ELSEIF ABL:親密 == 1 → LOCAL -= 2
ELSEIF ABL:親密 == 2 → LOCAL -= 1
; 好感度が低いと好感度低下
IF CFLAG:2 <= 50    → LOCAL -= 3
ELSEIF CFLAG:2 <= 100 → LOCAL -= 2
ELSEIF CFLAG:2 <= 250 → LOCAL -= 1
TFLAG:97 += LOCAL            ; 负 = 掉好感
```

**⇒ 完全不掉好感（= 不反感）的门槛：**

| 项 | 要求 |
|---|---|
| **`CFLAG:2`（好感度）** | **> 250** |
| **`ABL:親密`** | **>= 3** |

**最差情况**：好感 ≤50 且 親密 0 ⇒ **−6**（掉得很明显）

### 四、收益（按好感度分段给 `SOURCE:歓楽`）

```erb
IF CFLAG:2 <= 500       → SOURCE:歓楽 += CFLAG:2
ELSEIF CFLAG:2 <= 5000  → SOURCE:歓楽 += 500 + (CFLAG:2 - 500) / 3
ELSE                    → SOURCE:歓楽 += 2000 + (CFLAG:2 - 5000) / 5
SOURCE:受動 = 100 + 200 * ABL:従順
SOURCE:征服 = 100 + 200 * ABL:施虐属性
```

**⚠️ 注意"分段"**：好感 500 以下给全额、500~5000 给 1/3、5000 以上给 1/5 ——
**⇒ 边际递减**（官方防止高好感时收益爆炸）。

### 五、成败对收益的**倍率**（`:146-163`）

| 结果 | 倍率 | 情绪加成 |
|---|---|---|
| **大成功** | **×2.00** | `TFLAG:情緒BONUS = 30` |
| 成功 | ×1.00 | `= 20` |
| **失败** | 歓楽 **×0.10**、其余 ×0.50 | — |

### 七、📌 对我们的意义

**⚠️ 我们现在 prompt 里只有【对亲密举动的接受程度】= `CFLAG:態度`（性方面的合意）** ——
**那是"能不能做性的事"，不是"日常被摸会不会烦"** ✓ **两件事。**

| 语义 | 官方判据 | 我们注入了吗 |
|---|---|---|
| **性方面的合意** | `CFLAG:態度`（`>=500 主动迎合 / >=300 配合 / >=150 勉强`）| ✅ 【对亲密举动的接受程度】|
