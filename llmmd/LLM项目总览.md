## 1. 一句话说明

让 eraTW 里**每个角色都能用 LLM 自由对话**：她的台词不再是预设文本，
而是模型按**角色本人的性格 + 当前处境**实时生成的；同时对话会**真实影响游戏数值**，
并且**跨对话记住你们之间发生过的事**。

---

## 2. 你现在能做什么（玩家视角）

- 走到她面前 → 菜单选 **【自由对话】** → 直接打字说话
- 她**知道现在几点、在哪、天气如何、你俩什么关系、你累不累**
- 她会**陪着做事**（帮忙干活 / 一起运动 / 静坐发呆…），消耗和收益**照抄官方指令**
- 她**有记忆** —— 你陪她做过的事、你告诉过她的身份，她会记着
- 她会**挽留你**（越亲密越不想让你走），也会**在睡前赶你去休息**
- 她的**欲求不满度**会变，而且**结合关系与性格**决定怎么表现
- 每场对话结束会给 **`###DELTA###`** 数值块，由系统结算好感/情绪/信赖

## 3. ★★★ 核心架构：两阶段（**这是骨架**）

```
┌─ 判定阶段 ─────────────────────────────────────────┐
│  输入：困意 / 体力 / 关系 / 环境 / 玩家输入         │
│  ① @LLM_SLEEP_CHECK   → 她要收尾去睡吗（按亲密概率）│
│  ② @LLM_BYE_CHECK     → 玩家在道别吗？接受还是挽留  │
│  ③ 体力阈值           → 他快撑不住了吗              │
│  ④ @LLM_DECIDE_ACTION → ★ 算出**唯一的** LLM_ACTION │
│  ⇒ 这些数值**到此就用完了**                         │
└────────────────────────────────────────────────────┘
                        ↓
┌─ 对话阶段 ─────────────────────────────────────────┐
│  ⑤ @LLM_ACTION_HINT → 把**结论 + 相关数值**         │
│     合成**一句话**（"你决定留住他，因为你……"）      │
│  ⑥ 基础事实层照常注入（地点/时间/天气/关系/记忆…）  │
│  ⑦ 【最重要的表达规则】—— 状态不是清单              │
└────────────────────────────────────────────────────┘
                        ↓
┌─ 结算阶段 ─────────────────────────────────────────┐
│  ⑧ @LLM_APPLY_DELTA → 好感/情绪/信赖/体力/时间      │
│  ⑨ 按 `LLM_ACTION` 决定是否结束对话                 │
└────────────────────────────────────────────────────┘
```

**⚠️ 为什么这样分（踩坑换来的）**：
改之前是"**并行撒网**" —— 六个模块各自往 prompt 里塞一段带 ⚠️ 的指令，
一轮最多塞进 5 条 ⇒ 模型只能**每条都回应一下** ⇒ 台词变成"**状态面板念了一遍**"。

**⇒ 现在的规则：事实可以有很多条，行动只能有一个。**

**⚠️ 官方的做法也是这样**（`@自由行動処理` 按 `Activity_Type` 分派、
`@SOURCE_CHECK` 先累积再一次性结算）—— 我们是照着学的。

### `@LLM_DECIDE_ACTION` 的优先级（第一个成立的赢）

| 码 | 行动 | 说明 |
|---|---|---|
| 2 | **挽留** | 玩家发起的，最该回应 |
| 3 | **送别** | 同上 |
| 4 | **心疼他** | 比"她自己的困"更紧急 |
| 5 | **收尾去睡** | — |
| 6 | **憋着**（想要但地方不对）| — |
| 7 | **欲求不满**（想撩）| 最弱，上面任何一个都能盖过 |
| 0 | 平常闲聊 | **仍然联动关系与欲求**（作为底色）|

### 4.3 数值联动

| 方向 | 内容 |
|---|---|
| **她 → 游戏** | 好感度/情绪（`###DELTA###`）、信赖度、体力气力（`DOWNBASE` 结算）、技能经验、`SOURCE:歓楽/受動/征服` |
| **游戏 → 她** | 上面那张感知表 |
| **陪伴/帮忙** | **照抄官方 `"ソース"` 分支** —— 官方的数值效果自动全拿到（含 `SOURCE:征服`→優越）|
| **欲求不满度** | 挽留时 **+上限的 1/3**（恋慕以上）；≥500 让逆推门槛降低 |
| **关系分级** | ★ `@LLM_REL_RATE(档位, 用途)` **一张表管住所有功能的平衡** |

## 8. 已知的坑（写代码前**务必**看 `LLM_ERB语法避坑.md`）

**最常犯的五个（本项目都栽过多次）：**

1. **`SIF` 只绑紧随的一行**，且**后面不能跟 `ELSE`/`ELSEIF`/`ENDIF`**
   → 多行判断一律用 `IF … ENDIF`
2. **`%…%` 只装字符串** —— 数值必须用 `{…}`
3. **`DOWNBASE` 是"待扣量"**，必须 `CALL SOURCE_DOWNBASE(角色)` 结算**并手动清零**
4. **同一件事不能两处各判一次** —— 用统一入口（本项目栽过 **6 次以上**）
5. **行的开头必须是合法字符** —— 注释必须 `;` 开头。
   实测事故：注释里误敲 `>`，游戏直接报
   `Lv2:使用不正确的文字作为行的开始` 并**停止运行**。

### `tool\erb_check.py` 现在检查 **8 项**

| # | 检查 |
|---|---|
| 1 | 缩进 / 配对（IF/FOR/SELECTCASE…）|
| 2 | 引号配平 |
| 3 | `%` 配平 |
| 4 | `SIF` 多行 / `SIF` 后跟同缩进 `ELSE/ENDIF` |
| 5 | 数值变量被写进 `%…%` |
| 6 | 跨函数变量（声明与使用不在同一函数）|
| 7 | 容量（`#LOCALSIZE` / `#LOCALSSIZE` 是否够）|
| 8 | **行首合法性**（markdown 残留 = error；CJK 开头 = warn）|
