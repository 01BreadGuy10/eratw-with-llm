# eraTW 「合意」系统调研

> 调研时间：2026-09 ｜ 目的：搞清游戏里「合意」是什么、有哪几种、各自的效果
> 出处均标注了文件名与行号，可直接对照源码。

---

## 1. 「合意」是什么

**一句话**：它是游戏用来记录「**她已经同意和你做某类事**」的一组**位标志**。

- **存储变量**：`CFLAG:角色:既成事實`（编号 **1**，`AutoConst_CFLAG.ERH:7`）
- **不是布尔值**，是**位集合** —— 一个整数里每一位代表一种合意
- **获得时会给黄色提示**：`获得了和%角色%的合意`（`COLORMESSAGE(..., C_YELLOW, 2)`）

---

## 2. 全部合意位（`DIM.ERH:305-313`）

| 位 | 常量 | 含义 | 实际使用次数 |
|---|---|---|---|
| `1p0` | `合意_接吻` | 接吻 | 24 |
| `1p1` | **`合意_诶嘿嘿`** | **性行为** | **151** ← 核心 |
| `1p2` | `合意_恋人` | 恋人 | 6 |
| `1p3` | `合意_肛門` | 肛门 | **0** |
| `1p4` | `合意_手奉仕` | 用手伺候 | **0** |
| `1p5` | `合意_足奉仕` | 用脚伺候 | **0** |
| `1p6` | `合意_口奉仕` | 用口伺候 | **0** |
| `1p7` | `合意_胸奉仕` | 用胸伺候 | **0** |
| `1p8` | `合意_股奉仕` | 股间伺候 | **0** |

> ⚠️ **后 6 个是"占位"** —— 定义了常量，但**全项目 0 次使用**。
> 推测是原版规划过、或为后续扩展预留的。**不要以为它们生效了。**

**两种等价的写法**（源码里混用，别被绕晕）：

```erb
GETBIT(CFLAG:角色:既成事實, 1)      ; 读"位 1"
CFLAG:角色:既成事實 & 合意_诶嘿嘿     ; 同一个意思（1p1 = 2）
```

## 3. 三个**真正生效**的合意，各自的效果

### ① `合意_接吻`（位 0）—— 解锁接吻

| 效果 | 位置 |
|---|---|
| **没这个合意 → 接吻动作直接不可用**（`接吻 = 0`）| `COMF0 愛撫.ERB:11` |
| **没这个合意 → "搂抱"门槛 +20** | `抱き寄せ必要値()`，`ATTITUDE.ERB:350-351` |
| 影响"甲斐性無"模式下的接吻判定 | `COMF312 キスする.ERB:298` |

> 注意：接吻还有**别的前置** —— 双方都要有接吻经验（`EXP:PLAYER:キス経験` / `EXP:キス経験`）、
> 没有口部污垢、没戴口球。合意只是其中一道门。

### ② `合意_诶嘿嘿`（位 1）—— **最重要**，标记"你们已经做过了"

| 效果 | 位置 | 说明 |
|---|---|---|
| **大幅降低"她今晚想留宿"的门槛** | `MOVEMENT2.ERB:388-391` | 没有时加 `一線越えない×2 + 貞操×2` |
| **可以脱她下半身内衣** | `CLOTHES_下半身下着_ずらし可能.ERB:1218` | 或者有 `TALENT:恋慕` 也行 |
| **不再被当作"无知"处理** | `情事発覚.ERB:324` | 影响"情事被撞见"的判定 |
| **提高"诱导逆推"的概率** | `AFTERTRA.ERB:906` | `!RAND:4` 时才触发，有合意是前提 |
| 影响裸体时的反应 | `Chara_data_26_紫.ERB:544,572` | 角色专属口上分支 |
| 影响"喘ぎ"等口上分支 | `NASIKUZUSI.ERB:83,92,125,236` | |
| 甲斐性無模式的相关判定 | `COMF311 抱き付く.ERB:201` | |

**本质**：它标记「**你们已经发生过关系**」。此后她对该类行为的**抵抗大幅下降** ——
所以它的使用次数（151）远超其它两个。

### ③ `合意_恋人`（位 2）—— 标记"已告白成功"

| 效果 | 位置 |
|---|---|
| **没有 → 约会后可以走告白流程**；有 → 跳过（已经是恋人）| `DATE_CMN.ERB:194` |
| 二周目（強くてニューゲーム）会**清掉这一位** | `強くてニューゲーム.ERB:125`：`CLEARBIT ..., 2` |

## 4. 怎么才能拿到合意

### 4.1 先算「合意判定」（一个数值，不是位标志）

`CFLAG:角色:合意判定`（编号 **19**），算法在 `ATTITUDE.ERB:42-84`：

```
基础分 = 0
  + 恋慕×100  + 思慕×30  + 愛欲×80  + 炮友×30        ← 陥落素質
  + min(親密,20)×10  + min(欲望,20)×5                 ← ABL
  + 欲情LV×5  + 好意LV×5                              ← PALAM（各上限 15 级）
  + 情緒/25  + (1000 - 理性)/25                        ← 越放松越高
  + 不埒刻印×20  + 快楽刻印×20
  - 反発刻印×30（相对時姦刻印而言）
  + 发情 50 / 催情药·媚药 30
  + 花园 40 / 香 30
  - 讨厌男人 70
  + 風騷 400            ← 有这个素质直接拉满
  + 甲斐性無 且基础 ≥100 时 +50
  + 催眠強度 × 4
```

### 4.2 判定值 → 态度档位（`CFLAG:態度`，编号 6）

| 合意判定 | 态度 |
|---|---|
| **≥ 500** | **3** |
| **≥ 300** | **2** |
| **≥ 150** | **1** |
| **< 150** | **0** |

> ⚠️ `CFLAG:態度` **不是"对玩家的整体态度"**，它是**性方面的合意程度** ——
> 这一点我们在 LLM 项目里踩过坑，详见 `LLM对话系统实现说明.md` §10.2。

### 4.3 「获得合意」的时机

`ATTITUDE.ERB:178-182`：

```erb
IF !ARG:1
	;補正無で押し倒さないと合意がつかない
	SETBIT CFLAG:ARG:既成事實 , 1
	CALL COLORMESSAGE(@"获得了和%CALLNAME:ARG%的合意",C_YELLOW,2)
ENDIF
```

**注释直译**：「**没有补正地推倒她，才能拿到合意**」。

⇒ 也就是说：**靠药物 / 催眠 / 发情之类的加成把她推倒，是拿不到合意的**
（要"正面说服"她才行）。这个设计挺讲究。

另外 `合意_接吻` 也会在特定事件里给（如 `M_KOJO_K1_3_事件系.ERB:196`
的"约会回家路上的初吻"）。

## 5. 容易混淆的几个相邻概念

| 名字 | 编号 | 是什么 | 和"合意"的关系 |
|---|---|---|---|
| `CFLAG:既成事實` | **1** | **合意位标志集** | ★ 就是它 |
| `CFLAG:合意判定` | **19** | **数值**（0~500+）| 决定态度；达标才可能获得合意 |
| `CFLAG:態度` | 6 | 态度档位 0~3 | 由合意判定换算而来 |
| `TALENT:合意誤認` | 299 | "**误以为**已同意" | 详见下节 |
| `TFLAG:キス合意取得` | 88 | 本次接吻是否已取得合意 | 临时标记 |
| `M_FLAG:标记合意` | 12 | （未在本项目使用）| |

## 6. `合意誤認`（TALENT 299）—— 一个特殊状态

**"误以为已经同意了"**，通常由**催眠 / 药物**一类的效果赋予。

| 效果 | 位置 |
|---|---|
| **态度 < 2 时被强制拉到 2**，且 `合意判定` 提到 300 | `ATTITUDE.ERB:95-99` |
| **愤怒额外衰减** `Lapse×10`（她不容易生气）| `BASE自然変動.ERB:118-119` |
| **每晚重置**（是临时状态，不会永久留下）| `EVENTTURNEND.ERB:21`：`TALENT:LOCAL:合意誤認 = 0` |
| 影响"情事被撞见"的判定（和真合意等效）| `情事発覚.ERB:387` |

> **区别**：真合意会**永久**留在存档里；`合意誤認` 只是**当晚**让她表现得像同意了。
> 所以它常被用在"催眠"这类一次性场景。

## 7. 对 LLM 项目的意义（顺带）

### ★ 已落地：合意已接入「持久记忆」管线（2026-09）

**实现**：`@LLM_BUILD_SYSTEM_PROMPT` 里读三个生效的位，拼成一段注入 prompt：

```erb
LLM_CONSENT = ""
IF GETBIT(CFLAG:(LLM_CID):既成事實, 0)
	LLM_CONSENT = "你们接过吻"
ENDIF
IF GETBIT(CFLAG:(LLM_CID):既成事實, 1)
	... 追加 "你们已经有过肌肤之亲"
ENDIF
IF GETBIT(CFLAG:(LLM_CID):既成事實, 2)
	... 追加 "你们已经是恋人了"
ENDIF
```

注入形态：

```
【你们之间已经发生过的事】你们接过吻；你们已经有过肌肤之亲；你们已经是恋人了
（⚠️ 这些是**已经发生的事实**，不是猜测 —— 你可以自然地提起、
  当作你俩之间的默契；但**别刻意炫耀、也别每轮都提**。）
```

**⚠️ 它和 `LLM_MEMO`（模型自己写的持久记忆）的区别很重要**：

| | `LLM_MEMO` | **合意注入** |
|---|---|---|
| 谁写的 | **模型**自己判断该不该记 | **游戏已经记录好的事实** |
| 存哪 | `LLM_MEMO`（4 个槽位）| 不占槽位，直接读 `CFLAG:既成事實` |
| 可靠性 | 概率性（按好感度掷骰）| **100% 可靠** |
| 该不该有 | 会随好感度浮动、会淘汰 | **发生过就是发生过** |

⇒ **"已经发生过的事"属于**客观事实**，不该受"记不记得住"影响，所以单独读、单独注入。**

只取**真正生效的三个位**（接吻 / 诶嘿嘿 / 恋人）——
后 6 个是占位，读它们只会永远得到 0。

### ★ 和好感度的联动（双向，且已接入注入）

**方向上其实有两条，而且第一条是游戏原生的：**

#### ① 好感度 → 合意（游戏原生）

`ATTITUDE.ERB:20-40` 里，**好感度与信赖度直接给「合意判定」加分**：

```erb
SELECTCASE CFLAG:角色:2          ; 好感度
	CASE 10001 TO 30000 → 150 分
	CASE 30001 TO 50000 → 200 分
	CASEELSE            → 300 分
ENDSELECT
SELECTCASE CFLAG:角色:信赖度      ; 信赖度也参与
	CASE <= 100   → −50
	CASE 501~750  → +30
	CASE 751~1000 → +50
	CASE >= 1001  → +100
ENDSELECT
; 再叠加：陥落素質（恋慕×100 / 愛欲×80 / 思慕×30 / 炮友×30）
;         ABL、PALAM、情緒、理性、刻印、药物…
```

⇒ **好感度就是"能不能拿到合意"的主要来源之一**，这部分不用我们做。

#### ② 合意 → 后续一切（游戏原生）

`合意_诶嘿嘿` 全项目 **151 处**使用，而且**大量是"合意 × 恋慕"的组合**：

| 判定 | 位置 |
|---|---|
| 可以脱下半身内衣 | `CLOTHES_..._ずらし可能.ERB:1218`：`合意_诶嘿嘿 \|\| 恋慕` |
| 约她去没人的地方 | `M_KOJO_K23_1_依頼.ERB:1287`：`合意_诶嘿嘿 && 恋慕` |
| 某段专属剧情 | `M_KOJO_K36_1_イベント.ERB:11868`：`(恋慕\|\|恋人\|\|炮友\|\|愛欲) && 合意_诶嘿嘿` |

⇒ **同一份合意，配上不同的好感度，能解锁的东西完全不同。**

#### ③ 我们的注入也做了这层区分（2026-09 补）

**这是最容易漏的一点**：同样是"已经有过肌肤之亲"，
**两情相悦**和**被推倒/药物造成**，她的心态可以完全相反 ——
用同一句话注入，两种情况就会演成同一副样子。

```erb
IF GETBIT(CFLAG:(LLM_CID):既成事實, 1)
	IF CFLAG:(LLM_CID):2 >= REQUIRED_FAVOR_恋慕
		LLM_CONSENT += "你们已经有过肌肤之亲（两情相悦，那是很自然的回忆）"
	ELSEIF CFLAG:(LLM_CID):2 >= REQUIRED_FAVOR_思慕
		LLM_CONSENT += "你们已经有过肌肤之亲"
	ELSE
		LLM_CONSENT += "你们已经有过肌肤之亲（⚠️ 但**那件事你其实还没完全消化** ——"
		LLM_CONSENT += "当时关系还没到那一步，提起来你会有点不自在，可能回避或转移话题）"
	ENDIF
ENDIF
```

**三档心态**：

| 好感度 | 注入的措辞 | 她该有的表现 |
|---|---|---|
| **≥ 恋慕（3000）** | 两情相悦，自然的回忆 | 坦然、甚至主动提 |
| **≥ 思慕（1500）** | 中性陈述 | 自然，不特别强调 |
| **< 思慕** | **还没消化，会不自在** | 回避、转移话题、别扭 |

> ⚠️ 第三档正是**"被推倒 / 药物 / 逆推"**造成的常见情况 ——
> 有了这段，她不会莫名其妙地对一个关系还浅的人表现得亲密。

#### ④ 错配的**代价**：好感、信赖、愤怒三样一起动（2026-09 补）

⚠️ **上面那三档心态只是"她怎么说话"，还不够** ——
如果强推没有任何实际代价，"关系浅也能推"就会变成最优解。
所以进场时（`@LLM_CHAT_LOOP` 最前面）会调一次 `@LLM_CONSENT_GAP`：

**触发条件**（三条都要满足）：

| # | 条件 |
|---|---|
| 1 | 有 `合意_诶嘿嘿`（已经发生过）|
| 2 | **好感度 < 思慕（1500）** —— 关系还没到那一步 |
| 3 | `TCVAR:角色:339` 未设（**没罚过**）|

**惩罚**：

| 项 | 量 | 依据 |
|---|---|---|
| **好感度** | **−100** | 官方一次会话才 +4~10 ⇒ 等于十几次白聊 |
| **信赖度** | **−30** | `ATTITUDE.ERB:27-40` 的信赖分档是 100/300/500/750/1000 ⇒ **正好掉一档** |
| **愤怒** | **+150** | 官方一次轻冒犯是 +139~+231（捏脸/戳脸），强吻 +578 ⇒ 取 150：明显生气但没到翻脸 |

**⚠️ 三个刻意的设计选择**：

1. **`TCVAR:角色:339` 把关，只扣一次** ——
   否则每进一次对话扣一次，数值会被无限磨掉（那是 bug 不是设计）。
2. **惩罚在"她决定愿不愿聊"之前施加** ——
   否则这次她还用原本的语气开口，惩罚下次才生效，很割裂。
3. **刻意不动 `MARK:反発刻印`** ——
   那个在官方设定里**几乎不可逆**（刻印 2/3 连道歉都消不掉），
   写进去等于永久拉黑。**愤怒会自然衰减，是"可以哄回来"的惩罚。**

**⚠️ 顺带的好处**：愤怒会被 `LLM_MOOD` 读到并注入 prompt ——
**她的语气会自己变**（烦躁、没好气），不用我们额外写台词。
而且愤怒够高时，她下次可能**直接拒绝交谈**（`@LLM_REFUSE_REASON` 里本来就有愤怒判定）。

**进场时会提示**：
```
（%角色%看了你一眼，神情有点冷。）
```
只给这一句，**不报数值** —— 数值提示归 `@LLM_APPLY_DELTA`，
而且这也不是"这一轮聊出来的"，是旧账。
