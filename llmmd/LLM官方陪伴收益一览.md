> **用途**：用户要看官方做法，之后决定**我们的陪伴系统**怎么给收益。
> **数据来源**：`ERB\...\FREE_ACT_*.ERB` 的 `"ソース"` / `"完了"` 分支（**逐行抄的**）。
> **生成时间**：2026-09-18

## 一、官方的收益结构（**三个维度**）

```
① 消耗：DOWNBASE:MASTER:*  /  DOWNBASE:CHARA:*
   ⇒ 体力 / 气力，**累积待扣**，回合末由 @SOURCE_DOWNBASE 真的扣掉

② 收益：SOURCE:CHARA:歓楽 / 受動 / 征服 / 反感
   ⇒ ★ **不直接加好感度** —— 先写进 SOURCE，
      回合末由 @SOURCE_CHECK 换算成 PALAM:好意 等 ⇒ 再影响好感度 ✓
   ⚠️ 所以我们**在自由对话里读不到"最终好感度"**，
      只能读 SOURCE（**那正是 @LLM_APPLY_DELTA 里 LLM_SRC_ANY 标记的用途**）

③ 经验：EXP:MASTER:* / EXP:CHARA:*
   ⇒ 「完了」分支里还会给 **她** 一份经验（通常是 += 1~3）
```

### ★ `SOURCE` 公式的共同形状

```
SOURCE:CHARA:歓楽 = (基数 + (ABL:CHARA:親密 + 某技能/素质) × 倍率) × 時間係数
SOURCE:CHARA:受動 = (基数 + (ABL:CHARA:従順 + 同一项)   × 倍率) × 時間係数
SOURCE:CHARA:征服 = (…)                                  × 時間係数   ← 只有部分活动有
```
**⇒ 关键**：**收益和 `ABL:親密`（关系）+ 某项技能（玩家或她的）挂钩** ✓
**⇒ 而 `時間係数`** = `LLM_FACTOR = MAX(陪的分钟数 / 10, 1)`（我们调的时候传的）✓

## 三、从官方数据能读出的**三条设计规律**

**① 收益和"技能"挂钩，不只是好感**

```
运动 → 玩家戦闘能力
钓鱼 → 玩家釣りLv
做饭 → 玩家料理技能
读书 → 玩家教養
喝酒 → 她酒耐性
买东西/放松 → 好感度係数（纯关系）
```
**⇒ 玩家**在这件事上越擅长 ⇒ 她越开心** ✓
**⇒ 那让"一起做"有了**成长感**** ✓✓✓

**② "征服"只在少数活动里**

**⇒ 只有**运动 / 喝酒** 有 `SOURCE:征服`** ⚠️
**⇒ **而**其余**只给 `歓楽`（+ 受動）** ✓
**⇒ **说明**官方把"征服感"留给**有竞争/对抗性的活动**** ✓✓✓

**③ 收益分层很明确**

```
运动        三项 + 基础 150     ← 最高
喝酒/钓鱼   三项或两项 + 150
买东西      一项 + 基础 200      ← 基数高但只有一项
扫除/做饭/读书 一项 + 基础 100
放松        一项 + 基础 100，但**倍率只有 10** ← 明显低
吃饭/吃零食 **零收益**            ← 官方没做
```

## 四、对照：**我们系统现在的做法**

| 项 | 官方 | **我们** |
|---|---|---|
| **建立陪伴时** | 走一遍 `"ソース"` + 立刻结算 `DOWNBASE` | ✅ **一样**（`:4806` `TRYCALLFORM ... "ソース"`）|
| **过程中每轮** | ★ **什么都不做**（`"行動中"` 分支只有消息）| ⚠️ **我们也不做**（**只有时间推进**）|
| **结束时** | `"完了"` 给 `EXP` | ⚠️ **官方回合末跑；对话里跑不到** |
| **额外好感** | ❌ 官方不给 | ✅ **我们给**（`:4848` 亲密类 +2 好感）|
| **信赖** | ❌ `SOURCE` 换算 | ✅ **我们直接给**（`TFLAG:信頼度管理 += LLM_TRUST`）|
| **写记忆** | ❌ | ✅ **我们写**"有一次他陪我一起看书" |

**⇒ 所以**我们**比官方多给了**：**额外好感 + 信赖 + 记忆** ✓
**⇒ **而**少的**：**过程中每轮的持续收益**（**官方也没有**）⚠️

## 五、⚠️ 给"我们定收益"的三个参考点

**① 官方其实**认可"只有一次结算"**
**⇒ `"行動中"` 分支完全不结算 —— 那是**刻意的设计**** ✓
**⇒ **而理由是**怕刷**（**我们的注释也写了**："否则好感度会连着刷"）✓

**② 如果要加"每轮收益"，**参照系应该是 `DOWNBASE` 而不是 `SOURCE`**
**⇒ 因为 `SOURCE` 是给回合末的**大额**结算用的** ✓
**⇒ **而每轮的小额** ⇒ **直接给 `CFLAG:2`（好感）或 `TFLAG:信頼度管理`** 更直接 ✓

**③ 官方的"收益/消耗"比**（**可以当标尺**）：

| 活动 | 她的体力消耗 | 收益基数 | 比 |
|---|---|---|---|
| 运动 | 20 | 150 | **1 : 7.5** |
| 钓鱼 | 10 | 150 | **1 : 15** |
| 做饭 | 10 | 100 | **1 : 10** |
| 放松 | **0** | 100（×10）| **不消耗** |

**⇒ 所以**官方让"累的活动收益高、轻松的活动收益低"** ✓
**⇒ **而**吃饭/吃零食** ⇒ **零消耗零收益**（**那更像是"剧情"而不是"玩法"**）✓
