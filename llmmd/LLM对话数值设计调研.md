# 自由对话的数值该给多少 —— 调研与建议

> 本文回答一个问题：**LLM 自由对话每轮给 好感度 / 情緒 / 愤怒 各多少，才和游戏本身的尺度对得上？**
>
> 结论先行：**好感度现在的设定基本合理，情緒和愤怒则小了 1~2 个数量级。**
>
> 调研对象：`eratw-sub-modding-main`（eraTW 4.981 汉化整合版 + mod）

---

## 0. 结论速览

| 数值 | 调整前 | 官方一次「会话」 | 官方尺度参考 | **调整后（已实施）** |
|---|---|---|---|---|
| **好感度** | ±3 / 轮<br>单场 ±5 | **+4 ~ +10** | 日常指令 `+2~5`，告白 `+30`，事件 `+100~1000` | **±3 / 轮，单场 ±10** |
| **情緒** | ±2 / 轮 | **+30 ~ +200** | 满值 **1500**；自然衰减每次行动 40~120 | **±40 / 轮，单场 ±200** |
| **愤怒** | ±2 / 轮<br>累积 6 触发拒绝 | 被拒时约 **+347** | 满值 **1000**；轻冒犯 +139~+231；自然衰减每次行动 50 | **±60 / 轮，拒绝阈值 300** |

**一句话**：好感度我们没给少（官方本来就只有 +4~10），但**情緒和愤怒给少了 25~200 倍** —— 以现在的数值，玩家几乎不可能通过对话把她的情绪或愤怒推到一个能被游戏感知的程度。

---

## 1. 游戏的数值是怎么流转的（先搞清这个）

普通指令（会话、泡茶、劝酒……）**不直接改好感度**，而是：

```
玩家执行指令（如 COM300 会话）
   ↓
设置 SOURCE（如 SOURCE:歓楽 = 200、SOURCE:反感 = 300）
   ↓
@SOURCE_CHECK —— 每次行动结束时的统一结算
   ↓
CALL FAVOR_CALC(TARGET)        ← 唯一的出口
   ↓
算出 TFLAG:97 = 好感度变化量
   ├─ CFLAG:2 += TFLAG:97                    （好感度）
   ├─ BASE:情緒 += MIN(情緒上昇値, 200)       （情緒）
   ├─ BASE:憤怒 += 憤怒上昇値                 （愤怒）
   └─ 屏幕打印「好感度＋{TFLAG:97}」          ← ★ 游戏自己就打印这个
```

**关键点**：
- **所有互动共用一个结算函数** `@FAVOR_CALC`（`TRACHECK_好感度上昇処理.ERB:8`）
- **它自己会打印 `好感度＋N`**（同文件 `:426`）—— 我们对话里的提示格式正是模仿它，风格一致
- 我们直接改 `CFLAG:2` / `BASE:情緒` / `BASE:憤怒` **绕过了 SOURCE 层** ——
  这是有意的（简化），但意味着**我们必须自己承担"给多少才合理"的判断**

## 2. 官方给多少

### 2.1 `@FAVOR_CALC` 里好感度是怎么算出来的

`TRACHECK_好感度上昇処理.ERB`：

```erb
; ① 基础：能力等级的平均值
TFLAG:97 += (ABL:ARG:従順 + ABL:ARG:親密) / 2

; ② 天赋修正（各 ±1~3）
叛逆 -2 / 自尊心 -1 / 坦率 +1 / 自制心 -1 / 感情缺乏 -1 / 抵抗 -1 / 献身 +1 …

; ③ 心情（-1 / 0 / +1）
TFLAG:97 += TALENT:ARG:15

; ④ 恋爱关系：思慕 +1、恋慕 +2（新版改为 ×1.2 / ×1.5 倍率）

; ⑤ 主人的魅力（新版）：容姿*3 + 魅力*6 + 魅惑*4 + 謎之魅力 + 人気*2

; ⑥ SOURCE 折算 —— 注意这一项是**饱和函数**，SOURCE 再大也只贡献固定上限
LOCAL += (50 - 10000 / (SOURCE:ARG:歓楽 + 2000))     ; 歓楽 最多 ~+50
LOCAL += (100 - 100000 / (SOURCE:ARG:情愛 + 1000))   ; 情愛 最多 ~+100
LOCAL += (20 - 20000 / (SOURCE:ARG:欲情 + 1000))     ; 欲情 最多 ~+20
LOCAL -= (50 - 10000 / (SOURCE:ARG:反感 + 200))      ; 反感 最多 ~-50
TFLAG:97 += LOCAL / 10                               ; ← 除以 10！

; ⑦ 反発刻印惩罚
TFLAG:97 -= (FLAG:4 + 1) * MARK:反発刻印

; ⑧ ★ 默认「只涨不跌」
IF MARK:反発刻印 >= 3 && TFLAG:97 < -3 → -3
ELSEIF ... 
ELSEIF TFLAG:97 < 0 → TFLAG:97 = 0        ← 负值一律归零！

; ⑨ 上限
CFLAG:ARG:2 = LIMIT(CFLAG:ARG:2, 0, 1000000)
```

**两个重要结论**：
1. **好感度是有意"封顶"的** —— SOURCE 项经 `饱和函数 / 10` 后，一次互动最多贡献 **+5 左右**
2. **官方默认不让好感度下降**（负值归零），只有反発刻印和"强行"才会扣

**这也是我们当前 ±3 并没有给小的原因** —— 官方一次会话就是 +4~10。

### 2.2 官方「会话」指令给的具体数值

`ERB\コマンド関連\COMF\日常系\COMF300 会話.ERB:13`：

```erb
SOURCE:歓楽 = 200                                    ; 基础值
IF ABL:親密 <= 1   SOURCE:歓楽 += 親密 * 30          ; 200 ~ 230
ELSEIF 親密 <= 3   SOURCE:歓楽 += 200 + 親密 * 30     ; 260 ~ 290
ELSEIF 親密 <= 5   SOURCE:歓楽 += 500 + 親密 * 30     ; 650 ~ 800
ELSEIF 親密 <= 8   SOURCE:歓楽 += 750 + 親密 * 50     ; 1150 ~ 1400
ELSEIF 親密 <= 10  SOURCE:歓楽 += 1000 + 親密 * 50    ; 1450 ~ 1500
ELSE               SOURCE:歓楽 += 1600 + 親密 * 30    ; 1900+
SOURCE:歓楽 = LIMIT(SOURCE:歓楽, 0, 5000)

SOURCE:受動 = 100 + 100 * ABL:従順
SOURCE:征服 = 100 + 100 * ABL:施虐属性

; 成否倍率：失败 ×0.10 / 成功 ×1.00 / 大成功 ×2.00
; 话术技能倍率：0级 ×0.20 / 1级 ×0.40 / 2级 ×0.70 / 3级 ×1.00 / 4级 ×1.20 / 5级+ ×1.50
```

**折算后的实际效果**（我按公式手算）：

| 场景 | SOURCE:歓楽 | 折算后 LOCAL | **好感度** | **情緒** |
|---|---|---|---|---|
| 话术3级、親密0、成功 | 200 | ~47 | **+4** | **~15** |
| 话术5级、親密5、成功 | 975 | ~48 | **+4** | **~96** |
| 话术5级、親密5、大成功 | 1950 | ~48 | **+4** | **~96** |
| 话术5级、親密10、大成功 | ~3000 | ~49 | **+4** | **~160** |

> 情緒公式：`情緒上昇値 = MIN(ABL:親密 + 1, 10) * LOCAL / 3`
> 所以**情緒随亲密度放大**（親密0 → ~15，親密10 → ~150），而**好感度恒定 +4 左右**。
> 这是官方刻意的设计：**关系越深，同样一次聊天带来的情绪波动越大。**

### 2.3 尺度与自然衰减（决定"给多少才留得住"）

**满值（MAXBASE）—— 从角色 CSV 读，每个角色不同**：

| 项目 | 值 | 出处 |
|---|---|---|
| `MAXBASE:情緒` | **1500** | `CSV\Chara\Chara1 霊夢.csv`（各角色同量级，但**不要硬编码**） |
| `MAXBASE:憤怒` | **1000** | 同上 |
| `MAXBASE:理性` | **1000** | 同上 |
| 好感度 | `0 ~ 1000000`（实际有效区在几百~几千；恋慕门槛 3000、思慕 1500） | `TRACHECK_好感度上昇処理.ERB:415` |

> **本文早期版本**写的是"情緒 ≈ 2000 / 憤怒 ≈ 1500"，那是从公式里的常数
> `(2000 - BASE:情緒)` 和 `(1500 - 親密*100)` **反推**出来的，**并不准确** ——
> 那两个常数只是公式的标度参数，不是上限。**已按 CSV 实测值修正。**
>
> ⇒ 所以代码里**一律用 `MAXBASE:角色:情緒`**，绝不写死 1500/1000。

**自然衰减**（`MOVEMENTS\BASE自然変動.ERB`，`Lapse` = 本次推进的分钟数）：

```erb
; 情緒：不在同一位置时（:21）
BASE:ARG:情緒 -= Lapse * 4 * (BASE:ARG:情緒 + 500) / 500
;   Lapse=10、情緒=0    → 掉 40
;   Lapse=10、情緒=500  → 掉 80
;   Lapse=10、情緒=1000 → 掉 120

; 憤怒：总是衰减（:115）
BASE:ARG:憤怒 -= Lapse * 5 / (CFLAG:ARG:ブチギレ + 1)
;   Lapse=10、非暴怒 → 掉 50
```

> **这一条是判断我们数值合不合理的核心依据**：
> 玩家随便走一趟（约 10 分钟）情緒就掉 40~120。
> **我们给 ±2，等于"聊 20 轮攒的 40 点，走一步就没了"。**

### 2.4 被拒绝时官方给多少

`COMF300 会話.ERB:31`：

```erb
IF MARK:反発刻印 >= 3
	PRINTFORML %CALLNAME:TARGET%似乎不想理睬%CALLNAME:MASTER%的样子
	SOURCE:反感 = 300              ← 巨大的反感
	BASE:MASTER:気力 -= 100
	RETURN -1
ENDIF
```

经 `憤怒上昇値 = SOURCE:反感 * 3 * (2000 - 情緒) * (500 + 理性) / ((2000 + 情緒) * (500 + MAXBASE:理性))`
折算（情緒500、理性250）：**愤怒 ≈ +400**。

**所以"她拒绝你"这件事，官方给的是愤怒 +400 量级 —— 我们给 +2。**

## 4. 差距分析

| 项目 | 官方一次互动 | 我们一轮对话 | 倍数差 | 问题 |
|---|---|---|---|---|
| 好感度 | +4 ~ +10 | ±3 | **≈1 倍** ✅ | 量级对，但"单场 ±5"约等于官方聊一次 |
| 情緒 | +15 ~ +200 | ±2 | **小 10~100 倍** ❌ | 一场 20 轮才 ±40，一次时间推进就衰减掉 |
| 憤怒 | 被拒 +400 | ±2 | **小 200 倍** ❌ | 我们的"愤怒"实际上只驱动自己的计数器和立绘表情，游戏状态几乎不动 |

**后者还有一个连带影响**：`@LLM_SHOW_FIGURE` 用 `BASE:憤怒 >= 500` 判定愤怒表情 ——
我们的 +2 永远到不了 500，**所以"被激怒"时立绘不会变成愤怒脸**。

## 5. 最终采用的数值（**已实施**）

### 5.1 具体数值

| 数值 | 单轮 | 单场累计上限 | 理由 |
|---|---|---|---|
| **好感度** | **±3** | **±10**（原 ±5） | 官方一次会话 +4~10；一场 20 轮对话 ≈ 官方 2~3 次会话 |
| **情緒** | **±40** | **±200** | 官方一次会话 +30~200；官方单次硬上限也是 200 |
| **愤怒** | **±60** | （不设，靠 `MAXBASE` 兜底） | 官方轻冒犯 +139~231；一次"被无视" +347 |

> 落点比本文最初的建议略保守（情緒 ±40 而非 ±50、愤怒 ±60 而非 ±100），
> 取的是"一轮对话 ≈ 官方一次互动"的下沿 —— 因为对话是**连续多轮**的，
> 20 轮累计已经很可观，不宜每轮都顶格。

### 5.2 拒绝阈值（**已同步改**）

原来是"本场累积愤怒 `>= 6` 就赶人走"（配 ±2/轮 定的）。已改为：

```erb
LLM_ANGER_LIMIT = 300      ; 曾经是 6
```

即"**累积到官方一次『被无视』的量（+347），她才真的翻脸**" ——
按 ±60/轮 算约 **5 轮明显冒犯**；轻微冒犯（+20~30）则要更久。

### 5.3 prompt 也要跟着改（**已同步改**）

只改代码不改 prompt 是没用的 —— 模型仍会按旧范围吐 `±1`。所以一并改了：

- 范围说明：`b=情緒变化(-40~+40)　c=愤怒变化(-60~+60)`
- **新增【正确示例③】**（负面例子 `-2,0,60`），原来只有正面示例
- 加了一条强调：**"b 和 c 的量级要够大，别缩手缩脚；给成 ±1、±2 等于没有"**
  （实测模型对"不要太夸张"的旧措辞反应过度，一律给 0 或 ±1）

### 5.4 另一处连带修正

`@LLM_BUILD_SYSTEM_PROMPT` 里原本用 `CFLAG:角色:318` 当作"正在气头上"的判据，
已改为按 `BASE:憤怒` 分档（300 / 500 两档），与游戏自己的阈值对齐。

## 7. 专项：欲情（PALAM）与「按关系分级反应」

> 需求：**角色要根据和玩家的好感度，对同一句话做出不同反应** ——
> 好感度低时性骚扰会讨厌 + 愤怒；好感度高时则害羞 + 增加欲情。
>
> 调研结论：**官方已经有一套完整的同构机制**，而且相当精巧，我们照抄思路即可。

### 7.1 欲情的尺度：`PALAMLV` 是唯一正确的写法

`PALAM:欲情` **没有上限变量**（全项目搜不到 `LIMIT`/`MAXPALAM`），
它的"大小"完全靠**等级阈值数组 `PALAMLV`** 来表达：

**⚠️ 而 `PALAMLV` 有两套完全不同的阈值**（`ERB\初期設定.ERB:63-101`），
取决于 DLC 开关 `MAGIC_DLC_好感亲密重做`：

| 档 | 默认版 | 重做版 |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 100 | 100 |
| 2 | 500 | 200 |
| 3 | **3000** | **500** |
| 4 | 10000 | 1000 |
| 5 | **30000** | **2000** |
| 6 | 60000 | 5000 |
| 7 | 100000 | 10000 |
| 9 | 250000 | 50000 |
| 15 | 5000000 | 5000000 |

**⇒ 所以绝对不要写 `PALAM:欲情 += 3000`** —— 在重做版里那是 6 档的量，
在默认版里只是 3 档。**一律写 `PALAM:欲情 += PALAMLV:N`**，
语义是"加 N 档"，两套配置下体感一致。

**官方的判定也全都用等级**，例如：

```erb
IF PALAM:TARGET:欲情 >= PALAMLV:3        ; 有点感觉了
IF PALAM:TARGET:欲情 >= PALAMLV:5        ; 明显发情（"危险日+动物耳"发情条件）
IF PALAM:TARGET:欲情 >= PALAMLV:7        ; 药物/毒气触发的发情条件
IF PALAM:TARGET:欲情 >= PALAMLV:10       ; 很强烈
```

**官方的增量**（口上里可见）：`+= 10000` / `+= 5000` / `+= 100`
—— 按默认版算，`10000` ≈ 3~4 档，是"一次强刺激"的量级。

### 7.2 官方的「关系滤镜」：关系越深，同样的行为越不讨厌

**这是本次调研最有价值的发现**（`ERB\ステータス計算関連\SOURCE\SOURCE_EXTRA.ERB:107-140`，
注释就叫「陥落素質」= "沦陷素质"）：

```erb
; 恋慕 —— 反感/不快 只保留 20%！同时恭順/屈服/好意 +50%
IF TALENT:ARG:恋慕 && ASSIPLAY == 0
	CUP:ARG:反感 = CUP:ARG:反感 * (10 - 8 * TALENT:ARG:恋慕) / 10
	CUP:ARG:不快 = CUP:ARG:不快 * (10 - 8 * TALENT:ARG:恋慕) / 10
	TIMES CUP:ARG:抑鬱 , 0.50

; 愛欲 —— 反感/不快 保留 30%
ELSEIF TALENT:ARG:愛欲
	CUP:ARG:反感 = CUP:ARG:反感 * (10 - 7 * TALENT:ARG:愛欲) / 10
	TIMES CUP:ARG:抑鬱 , 0.40
ENDIF

; 思慕 —— 反感/不快 保留 50%
IF TALENT:ARG:思慕 && ASSIPLAY == 0
	CUP:ARG:反感 = CUP:ARG:反感 * 5 / 10
	CUP:ARG:不快 = CUP:ARG:不快 * 5 / 10
ENDIF

; 淫乱 —— 按等级继续减少
IF TALENT:ARG:淫乱
	CUP:ARG:反感 = CUP:ARG:反感 * (10 - 2 * TALENT:ARG:淫乱) / 10
ENDIF
```

**读法**：行为本身产生的反感是**一样的**，但关系深的人会**把累积的负面快速消解掉** ——
恋慕时只剩 **20%**。这就是"同样一句下流话，陌生人会翻脸、恋人只会脸红"的官方实现。

> 注意它作用的对象是 **`CUP:*`（累积值）**，不是当次增量 ——
> 也就是说关系滤镜是**持续生效**的，不是只在那一回合。

### 7.3 官方的「记恨」分级：累积 → 反感刻印

`ERB\ステータス計算関連\TRACHECK_刻印取得.ERB:167-227`：

```erb
刻印取得値 = CUP:ARG:反感 + CUP:ARG:不快          ; 负面累积总和
SELECTCASE 刻印取得値
	CASE 500 TO 1000      → MARK:反発刻印 = 1   + 心情不快=1 + ブチギレ=1 + 心情=-1
	CASE 1001 TO 2000     → MARK:反発刻印 = 2   + 従順/親密 -1
	CASE IS > 2000        → MARK:反発刻印 = 3   + 従順/親密 -2
ENDSELECT
```

**`MARK:反発刻印` 就是"她记恨你"的等级（0~3）**，而且：
- 刻印 ≥ 1 时，`@FAVOR_CALC` 会**开始允许好感度下降**（否则负值一律归零）
- 刻印 ≥ 3 时，**官方会话指令直接拒绝**（`COMF300 会話.ERB:31`）
- **道歉可以消除**：刻印 1 时用点心盒道歉能清零（`COMF303 謝る.ERB:109-113`）

### 7.4 官方的「她炸了」是一个现成函数

`ERB\COMMON.ERB:1378`：

```erb
@GET_ANGRY(ARG, 刻印付与)
CFLAG:ARG:心情不快 = 1
CFLAG:ARG:ブチギレ = 1
BASE:ARG:憤怒 = MAXBASE:ARG:憤怒      ; 愤怒直接拉满
TALENT:ARG:心情 = -1
MARK:ARG:反発刻印 = MIN(MARK:ARG:反発刻印 + 刻印付与, 3)
```

**"被彻底惹毛"的官方处理就是这五行**。我们要"真的激怒她"时可以直接 `CALL GET_ANGRY`。

### 7.5 「害羞 + 欲情」那一侧的官方依据

- `CUP:恭順 / 屈服 / 好意` 在恋慕时 **×1.5**（`SOURCE_EXTRA.ERB:109-112`）
  —— 即"关系深了，同样的亲密行为带来的好感/顺从更多"
- 欲情只升不降的正规通道是 **`SOURCE:欲情`**（走 `FAVOR_CALC` 管线），
  但直接 `PALAM:欲情 += PALAMLV:N` 在口上里也很常见
- **"害羞"在游戏里没有专门变量** —— 它靠 `TALENT:恥情`/`PALAM:恥情` 与口上文本表达。
  我们让 LLM 演"害羞"即可，不需要动数值

### 7.6 结论：我们该怎么做（**已实施**）

**核心原则：让模型判断「性质」，让 ERB 决定「效果」。**

模型不知道 `REQUIRED_FAVOR_恋慕 = 3000` 这种门槛，也不该让它知道
（否则它会在台词里报数字）。

**① 结算块加了第 4 个字段 `t` = 这句话的性质**

```
###DELTA###
a,b,c,t
```
| t | 含义 |
|---|---|
| 0 | 普通（寒暄 / 闲聊 / 正经话题 / 普通玩笑） |
| 1 | 亲昵或调情，但没有直接性意味 |
| 2 | **露骨的性骚扰 / 越界** |

prompt 里也明确写了：「**t 只描述玩家这句话的性质，与你的反应无关** ——
同样的 t=2，关系浅时你会生气、关系深时你会害羞，那是系统按关系决定的。
所以不要因为关系好就把 t=2 写成 t=1。」

**② ERB 侧按关系分级（用游戏自己的常量，不硬编码）**

`@LLM_APPLY_DELTA` 开头会**覆盖**模型给的效果：

| 关系（按优先级） | `t=2` 时的效果 |
|---|---|
| `TALENT:恋慕` / `TALENT:愛欲` | **害羞**：好感 +1、情緒 **+40**、愤怒 **−30**、**欲情 +`PALAMLV:3`** |
| `TALENT:思慕` 或 好感 ≥ `REQUIRED_FAVOR_思慕`(1500) | 尴尬嗔怪：好感 −1、情緒 −20、愤怒 +40 |
| 其余（关系尚浅） | **讨厌 + 明显愤怒**：好感 **−5**、情緒 −40、愤怒 **+150** |

> 关系尚浅时愤怒 +150 ⇒ **两轮就够到拒绝阈值 300**（陌生人被骚扰会直接翻脸）；
> 思慕档 +40 ⇒ 要约 8 轮；恋慕档 −30 ⇒ 不累积反而消解。

**③ 跨对话"真实记录"：存在 `TCVAR:角色:336`**

- 每次重新搭话时，先**按关系消解一次**（照抄官方系数）：
  恋慕 **×0.2** / 愛欲 **×0.3** / 思慕 **×0.5**，再自然消退 50
  → **关系越深越容易消气**；陌生人则会把上次的不愉快带进下次对话
- 累积到 **300** ⇒ 本场拒绝（沿用原阈值）
- **不写 `MARK:反発刻印`** —— 那个在官方设定里几乎不可逆，代价太大（用户明确排除）

**④ 欲情一律用 `PALAMLV:N`**

见 §7.1：有两套阈值表，写死数值会在不同 DLC 配置下差 6 倍。

### 7.7 `TCVAR:角色:336` 这个编号是怎么选的

| 依据 | 内容 |
|---|---|
| 已占用 | 335=「打西瓜参加」，341~344=特殊 Buff，**350~399 是「口上用確保領域」不能占** |
| 选用 | **336**（336~340 空闲） |

## 8. 一句话总结

> **好感度我们本来就是照着官方尺度给的（官方一次会话也才 +4~10），
> 问题出在情緒和愤怒 —— 它们小了 1~2 个数量级，
> 小到"聊一整天也抵不上游戏里走一趟路的自然衰减"。
> 已改为 情緒 ±40、愤怒 ±60，拒绝阈值 300。**
>
> **至于"按好感度分级反应"：官方早就有同构机制 ——
> 行为产生的负面是一样的，但关系深的人会把累积的负面消解掉
> （恋慕只剩 20%、愛欲 30%、思慕 50%），累积到 500/1000/2000 就依次记恨。
> 我们照这个思路做即可：模型只判断"是不是性骚扰"，分级交给 ERB，
> 门槛用 `REQUIRED_FAVOR_*`，欲情用 `PALAMLV:N`。**
